用go语言（必须是最新版的go语言）实现一个代理服务，场景是：

局域网里的服务器能同时访问公网和内网，该服务器将公网的web服务代理到局域网里提供服务，让局域网里其它设备可以断网考试（即通过这个go语言的代理来访问公网web考试服务）

这个代理要做到高性能（类似nginx反向代理，常规的注意事项都做好），常见静态资源扩展名（js、css、webp、json、mjs、字体、图片等，**不含 .html/.htm**）以 1 分钟时长缓存，减轻公网 web 服务器压力；**页面类 HTML 不缓存**（缓存键不含 Cookie，否则会话态页面会串号）。

打开时，如果没有配置，则交互式让用户填配置：

公网服务地址（必须是 完整url，包括http/https协议，没端口号就默认是80或443，如果有额外的 ”/“ 或额外的路径都自动去掉），填入后自动测试公网服务地址是否可访问，如果有问题就提示用户核对地址以及当前环境是否可访问，并让用户重新填写。

上游访问密码（具体用户名不向操作者展示）：可留空表示公网站点未对该入口启用访问口令。填写或留空后均会做一次访问校验（留空时若返回 401/407 会提示需填密码；有密码时 401/403 视为密码错误），通过后再询问内网端口。

内网服务端口号，填入后自动测试端口是否被占用，如果有问题就给出合理提示信息，并让用户重新填写。三项均通过后才写入 conf 并进入后续界面。

通过后则清空控制台界面，显示当前配置，以及滚动日志（即日志不会把配置信息区”顶“跑，而是在固定若干行滚动显示日志，同时在当前目录新建log文件夹，记录 log 文件， .log 文件名按小时为单位开新的，区分 info 和 error

所有 warning 和 error 计入 error 的log文件，正常请求计入 info

控制台里的样式要精美一些有高级感一些。

配置记录到当前目录的 conf 文件。

每次打开时，如果已有 conf 则先检测远端是否可访问（含 Basic 密码）、本地端口是否占用：检测阶段 **简短提示**（第几次、间隔前一行提示），**不按高频刷新**；最多 3 次、间隔 2 秒，**任意时刻按一次 Ctrl+C（SIGINT）即可中断**（与主程序信号处理衔接），不必等满三次；**失败或中断均不退出程序**，转入与「按 c c 重新配置」相同的交互式流程，请用户重填并写回 conf 后再启动。

如果没有conf 就交互式配置。

启动服务后，界面提示可用操作： 按两下 c 则停止服务并重新配置，按两下 t 则暂停服务。在暂停服务状态下，也可以按两下c去重新配置。在暂停服务状态下按两下s 则重新启动服务。

这些功能说明也要显示在正在提供服务的配置信息里。

功能键按一下的时候，显示已按下一次，并倒计时等待下一次，倒计时结束或用户按下其它键则认为用户取消该操作。

要支持编译到 windows 和 linux 两个系统的release（go语言原生支持的吧？你做好这件事）

该单文件工具要同时支持双击运行和命令行调用运行，要支持好 windows 和 linux 两个系统。
