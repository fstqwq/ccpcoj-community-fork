## 对拍设计

生产 PHP 按全场提交时间和 solution_id 顺序扫描，先截断各队各题真实 AC 后的提交，再进行公开视图投影。独立 Python 参考算法先按“队伍、题目”分组，在组内定位首 AC 并截断，再计算可见状态与排序。这减少了两个实现共享同一控制流错误的机会。

随机样例包含 1–30 队、1–12 题，待评测/AC/失败/CE/系统状态、乱序输入、相同提交时间、开始前、结束时及结束后提交。检查时刻为开赛、封榜前一秒、封榜起始秒、封榜中和解除封榜时刻。大规模阈值的 49/50/200 等情况由固定断言覆盖。

特别验证：封榜中已经真实 AC 的队伍再次提交，该次提交不会因先被改为 pending 而重新计入；这是简单“先遮蔽结果再统计”容易产生的错误。气球使用同一首 AC 过滤规则，首血并列时间通过 solution_id 唯一确定。

## 真实运行时的使用范围

当前环境没有预装 PHP，测试使用从同一 Web 镜像提取的 PHP 7.4.33 CLI。它能验证实际目标 PHP 版本的语法和核心执行，不等于 PHP-FPM 的完整站点部署。

MySQL 测试使用官方固定摘要镜像中的 MySQL 8.4.11 可执行文件。初始化阶段可执行 SQL，因此完成了业务表基线、旧库模拟、两列 ALTER，以及检查原有记录和新列默认值的数据库 CHECK 断言。自动迁移脚本的幂等性/锁处理另由桩连接验证。

尝试启动 MySQL 服务时，环境拒绝创建监听 socket，日志返回 `UNIX Socket : Operation not permitted`；环境也没有 Docker daemon。因此没有把数据库离线初始化冒充为 Web 到 MySQL 的真实连接测试。
