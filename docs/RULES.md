# 规则与参考实现的对应

规则依据为用户提供的《CCPC 新榜单模式说明》，日期 2026-09-14，原件附在本目录 `CCPC2026-rules.pdf`。另一依据为用户指定站点的公开前端资源；其资源地址和 SHA-256 记录在 `provenance/reference-assets.json`。

## 行为

| 规则 | 本实现 |
|---|---|
| 比赛最后一小时封榜 | `freeze = max(start, end - 3600)`，边界包含封榜起始秒 |
| 封榜前保留题数、罚时、提交状态 | 服务端计算，页面继续使用原榜单排名与显示框架 |
| 初始隐藏题号 | 公共响应移除隐藏题 ID/标题/全局颜色/原始提交，只含队伍专属 HMAC 键与公开统计 |
| 达到 50 支或 20% 队伍后揭示 | 默认采用参考站的 `min(50, max(1, floor(N/5)))`；后台可改为 fixed_50 或 ratio_20 |
| 各队独立排序 | 公开题按题号；隐藏 AC 按首次 AC 时间；其他已提交题按最后提交时间；未提交最后 |
| 封榜后原 XCPC 布局 | 公开所有题号，按题号对齐；封榜内结果显示 pending；解题数与罚时仅计算可见 AC |
| 忽略 AC 后全部提交 | 先按真实 AC 截断，再遮蔽封榜结果；重复提交不影响计数、时间、罚时或气球 |
| 封榜停止所有气球 | 队列、打印、服务端状态变更三处执行停止规则 |
| 首血去除题号对应关系 | 选择规则允许的“统一特殊气球”方案，所有首血为黑色 FB；没有实现全场首血序号方案 |
| 普通气球随机颜色 | 每队每题分配不同色，HMAC 决定随机排列；只向授权气球工作人员返回实际已 AC 的分配 |

参赛名单取原榜单的全部有效队伍，包含打星队，排除工作人员；没有提交的队伍仍计入阈值。默认阈值及这一口径贴近参考前端。少于 5 队时阈值下限为 1，避免“尚无 AC 已全部公开”。小型演练可显式选择固定阈值。

结果沿用原 XCPC 判定分类：0–3 为待评测，4 为 AC，5–10 为计罚失败，11 编译错误及更高系统状态不计罚也不进入榜单提交计数。待评测计入可见提交数量，不增加罚时。罚时以秒保存，每次有效错误增加 1200 秒。比赛开始包含、结束不包含；提交时间相同时按 solution_id 确定先后。重判会重新从完整提交序列计算。

达到封榜起点后，题号保持公开。结果遮蔽持续到 `end_time + frozen_after × 60`，到该时刻自动解除。比赛少于一小时会从开赛即封榜；测试时应注意这个设置。

## 接近参考站的部分

已经读取 `https://cpc.csgrandeur.cn/static/csgoj/contest/rank_ccpc.js`。它在已有榜单类上扩展 CCPC 行为，使用 `contest_rank_kind: 'ccpc'`，区分 `ccpc_meta.view: 'referee'`，支持 `threshold` 和 `frozen_show_all`，按公开区与隐藏区渲染。注释还说明隐藏题使用队伍内 HMAC 键。

本仓库同样在恢复出的原榜单上扩展，保留原皮肤、分组与排行代码，使用上述开关和元数据。规则计算放在服务端，前端消费完整 `ccpc_rows` 快照，避免客户端仍拿到真实题号。

明确的差异与未知：

- 参考 JS 在隐藏区只渲染已提交/已 AC 题。本实现依用户规则保留未提交的无题号空白格，并置于末尾。
- 参考站部署了更新的拆分版 `rank_core.js` 等模块；Docker 中的 2.0.40 尚未采用同一拆分。因此本实现新增兼容扩展，没有整套替换为不完整的线上前端。
- 参考站登录后的榜单 API、气球后端、密钥管理和现场打印流程无法从公开 JS 证明。这里的后端匿名、AC 去重、配色与停止发放逻辑是依据规则独立实现的，不声称恢复了线上私有后端。
- 公共榜单使用完整快照，禁用原增量客户端缓存及时间拖动回放。裁判视图继续使用原始结果；需要历史回放的公开版本应由服务端在对应历史时刻重新投影后另行提供，本次未实现该接口。
- 学校汇总显示公开题统计，不把各队匿名键错误合并成同一题；队伍总解题数与罚时仍参与原学校排行逻辑。
- 保留原直播榜，通过相同服务端快照和公共题区渲染；没有完成真实浏览器中的视觉验收。

## 数据边界

公开榜响应中的 `solution` 与 `contest_balloon` 为空；隐藏题不出现在 `problem` 列表里。每队隐藏格的键为比赛 ID、队伍 ID、题目 ID 的 HMAC，因此不能通过键值在不同队伍之间直接对齐题目。题目一旦揭示，改用公开题 ID。

比赛状态列表和单条状态查询，对普通参赛者限定为自己的提交。题目列表不展示全场 AC 数/提交数及固定气球颜色。CCPC 的 CCS 原始事件接口要求管理员凭据，避免从另一接口得到原题 ID 和全量提交。授权裁判和气球工作人员仍有其工作所需的数据。

这些限制用于按规则控制平台直接公开的数据，不宣称能消除队伍之间交流、观察做题顺序等造成的间接推断。HMAC 密钥与色板必须备份，并在整场比赛中保持不变。
